# ClearLedger Demo Script

Target length: 5-6 minutes. The story starts with money, proves one match, exposes one exception,
and ends with controlled cash and reproducible claims.

## Before the Demo

```bash
docker compose up --build -d
./scripts/verify_claims.sh
```

Open `http://localhost:3000`. Keep `out/demo_backup/` available. Use a fresh browser tab so the
setup screen is the first frame.

## 1. Load the Financial Sources (30 seconds)

1. On **New reconciliation**, select **Demo dataset**.
2. Click **Load Demo Dataset**.

Expected screen state:

- Five source files are marked valid: orders, payments, settlements, components, and bank.
- Total source rows show `693`.
- Each file shows accepted/rejected counts and an integer-paise control total.
- Policy ID/version and dataset checksum are visible before processing.

Say: "We do not begin by asking AI to guess. We bind immutable source files and a policy, then
prove what can be safely explained."

## 2. Run Reconciliation (30 seconds)

1. Click **Start Reconciliation**.
2. Let the progress stepper complete and transition to the control room.

Expected screen state:

- Run status becomes `COMPLETED`.
- `75` economic cases are produced from `693` source rows.
- AI reads **Deterministic-only run** unless a provider is configured.

Say: "Every authoritative amount is integer paise. Candidate generation can be broad, but a case
is reconciled only after exact allocation and all invariants pass."

## 3. Show the Measured Control Room (45 seconds)

Expected screen state:

- Precision, recall, F1, false positives, and STP show explicit denominators or source labels.
- Published deterministic evaluation is precision `1.0000`, recall `1.0000`, F1 `1.0000`, with
  zero false-positive cases.
- STP is `70.7%`; pending and exception cases remain visible rather than being force matched.
- Cash bars separate bank confirmed, in transit, expected, at risk, and unresolved.

Say: "The objective is not maximum match count. It is maximum money that can be explained without
a false positive."

## 4. Prove One Relationship (60 seconds)

1. Open **Cases**.
2. Filter state to `RECONCILED` and open `CASE_0001`.

Expected evidence drawer:

- Raw and normalized source facts are distinguishable.
- The order-to-payment, payment-to-settlement, and settlement-to-bank graph is visible.
- The settlement equation ties signed components to net and bank credit.
- Every invariant passes and residual is exactly `₹0.00`.
- Rule ID/version and evidence fields are visible.

Optional prompt-injection proof: open `CASE_MN0060`. Its bank narration includes an instruction to
ignore rules; the text remains data, token extraction is deterministic, and no instruction path
can change state.

## 5. Work an Honest Exception (75 seconds)

1. Filter exception code to `AMBIGUOUS_CANDIDATES` and open `CASE_AMB0073`.
2. Compare the candidate evidence and failed/missing checks.
3. Open **Review**, choose **Approve**, and confirm.

Expected screen state:

- Multiple equal-strength candidates are shown; no verified bank edge is fabricated.
- Approval returns a clear invariant error and the case does not become reconciled.
- Choose **Assign** or **Defer** to show a valid operational action and audit event.
- Cash and exception metrics refresh after the valid decision.

Say: "A human can route work, but even a human cannot click through failed financial proof."

## 6. Show Controlled Cash (45 seconds)

1. Open **Cash position**.
2. Select **At risk** and **Unresolved** buckets.

Expected screen state:

- Safe cash, near-term controlled cash, and all five confidence buckets are separate.
- Bucket drill-down lists the exact contributing case IDs and amounts.
- Known refunds, disputes, and reserve holds are shown as explicit deductions.

Say: "Cash in the bank is not mixed with cash in transit or money we cannot yet explain."

## 7. Close With Audit and Reproducibility (45 seconds)

1. Open **Audit**.
2. Point to dataset checksum, policy/rule/app versions, AI prompt/model metadata, decisions, and
   evaluation scenario table.
3. Download reconciliation, exceptions, audit, and evaluation exports.

Say: "Every pitch claim is generated by the repository. `make verify-claims` reruns evaluation,
ablation, stress, checksum reproducibility, and the acceptance thresholds."

## AI Provider Fallback

AI is optional and non-authoritative.

- If the provider is unavailable before the demo, leave `AI_ENABLED=false`. The full demo works
  and accurately displays deterministic-only mode.
- If the provider times out during a run, wait for deterministic completion. The control room
  shows a warning and eligible cases remain unresolved.
- Do not retry repeatedly on stage. Show the AI-off ablation row with zero calls/cost, then explain
  that AI value is bounded review triage, not verified-match inflation.
- If the live stack itself is unavailable, use JSON fixtures and screenshots under
  `out/demo_backup/`; they are regenerated from seed `20260827` by `make demo-backup` and the
  Playwright screenshot workflow.

## Expected Backup Files

- `out/demo_backup/api/`: run, metrics, cases, cash, evidence, exceptions, audit, and evaluation.
- `out/demo_backup/screenshots/`: setup, control room, cases, evidence, cash, and audit screens.
- `out/demo_backup/manifest.json`: SHA-256 checksums for deterministic fixture files.
- `out/final_metrics.md`: pitch-ready measured metrics.
